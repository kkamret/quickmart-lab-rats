# 배민 사례 보정·해석 기록

`docs/cases/baemin.md`의 검증 시나리오가 진실의 원천이다. 파라미터는 스펙 기준값의 ±50% 안에서만 조정할 수 있고, 조정하면 이 문서에 적는다.

## 1. 파라미터 보정: 없음

`effects.ts`의 `CALIB`는 **스펙 기준값 그대로**다(배수 1.0). 시나리오 14개가 보정 없이 통과했다.

### 스펙과 다르게 검사한 부분
- **#4, #5는 시드 400개 → 2,000개로 검사한다.** 400개로는 비율 추정 오차가 ±2%p라서 22.6%인 진짜 비율에서도 가끔 25%를 넘는다(실제로 한 번 26%가 나왔다). 시드 구간을 바꿔 통과시키는 대신 표본을 늘렸다.
- **순차 검정(sequential)의 위양성률은 약 7.5%** (α=5%보다 높음). 스펙의 경계식 `z_k = z_{α/2}·sqrt(K/k)`는 마지막 확인에서 보정 없는 1.96을 쓰기 때문이다. 스펙대로 구현했고 "α 유지"는 근사로만 성립한다. 정확히 맞추려면 상수 c를 따로 보정해야 한다(필요하면 스펙에서 결정).

## 3. 스펙이 모호해서 정한 해석

| 항목 | 해석 |
|---|---|
| 실험 1일차 요일 | 월요일. 요일 인덱스 `(day-1) % 7`, 5=토, 6=일 |
| 유입 | `52,000 × 요일 배수 × (1 ± 4% 노이즈) × (가게홈 0.56) × allocation`을 세그먼트 비중으로 나눔. 안드로이드만이면 ios 세그먼트 제외 (비중 0.59가 그대로 반영) |
| 램프 `10_50_100` | B 에 **배정된** 사용자 중 바를 실제로 보는 비율이 1일차 10%, 2일차 50%, 3일차~100%. 보지 못한 사용자는 대조군처럼 행동 → 효과 희석. 그룹 크기는 50:50 유지 |
| 램프 `10_week1_50_week2` | **그룹 크기 자체가** 1~7일 B 10% / A 90%, 8일~ B 50% / A 50%. 이래야 심슨의 역설이 생긴다 |
| `analysis_mode` | `pooled`는 전 기간 합산, `stratified`는 계획 배정비가 같은 연속 일차(층)별 비교를 역분산 가중으로 합침. 층이 하나면 같음. 램프 일차를 빼는 옵션은 없음 |
| SRM 기대값 | 계획 배정비(램프 반영)로 계산. 램프 자체가 SRM 을 만들지 않게 함 |
| 중간 확인 | 포함된 일차마다 누적 검정(첫 처치군 vs 대조군). peek_stop: p<α 첫날 종료. sequential: `|z| ≥ obfBoundary(k, K, α)` |
| 신규성 일차 d | 실험 일차 (1일차 = 1) |
| `unit` | session 은 모든 진짜 효과 ×0.55, SE ×(1/1.5). pageview 는 ×0.30, SE ×(1/2.0) |
| P2 버그 적용 조건 | `ramp = none` 일 때만(램프업으로 시작하면 초기 크래시 가드레일에서 먼저 잡아 고친 것으로 본다). 사전 QA 체크박스는 없음 |
| P2 버그 (노출 기준) | ios_old B 사용자 24%를 제거하고 남은 사용자의 이탈률 −0.04 |
| P2 버그 (배정 기준) | 사용자는 남지만 24%는 장바구니에 닿지 못하고(담기율 ×0.76) 크래시로 집계 → ios_old B 크래시율 약 0.25 |
| P2 크래시 효과 | 스펙에 P1(+0.0002)만 있어서 P2 도 같은 값을 유지 |
| P3 트리거 모델 | 사용자의 일정 비율(low 4.1%, high 18%)이 트리거 사용자. 이들은 장바구니에 담은 상태이고 담은 뒤 주문 비율 0.50(B +0.023), 평균주문금액 29,400(B +6.1%). 나머지는 기본 퍼널. 따라서 **coupon_ops=high 는 환경 자체를 바꾼다**(전체 전환율·평균주문금액이 올라감) |
| P3 비용 | 쿠폰 운영 확대 시 트리거 B 사용자 1명당 1,200원(가상) |
| `bar_click` | P1·P2 에서는 B 에만 존재하는 지표(메인으로 쓰면 거부). P3·P4 는 모든 그룹에 있음 |
| 협의 MDE | `mde_pp` 입력을 없애고 Primary 지표별 고정 MDE(`mde.ts`, 교육용 가상 값: 이탈 1.5%p, 전환 1.0%p, 금액 3% 등)를 쓴다. 계획 표본(P1 이탈률·14일·안드로이드 가게홈, α 0.05, 검정력 0.8)은 그룹당 49,005명(약 12일)으로 재측정. 이전 기본 MDE 2%p 대비 약 1.8배 |
| `achievedPower` | **진짜 효과 기준** (기댓값 경로에서 계산). 진짜 효과가 0 이면 팀이 정한 MDE 기준. 시나리오 #8 이 진짜 효과 기준의 검정력(0.15~0.35)을 요구한다. 단, 진짜 효과의 크기를 간접적으로 드러내는 값이므로 필요하면 조 화면에서 가리는 것을 M4 에서 검토 |
| 진짜 효과 | `panels._truth` (강사·AI 전용, `toTeamView`가 제거) |
| 플래그 | SHORT_DURATION: (1) 분석한 A 사용자 < 계획 표본, (2) 일찍 멈추지 않았는데 분석 일수가 7의 배수 아님, (3) 분석 일수 ≤ 7. MULTIPLE_TESTING: 보정 없음 + Primary 아닌 비교 m개의 1−(1−α)^m > 0.5. UNDERPOWERED: 달성 검정력 < 설계 검정력. SRM: p < 0.001(업계 관례). 근거는 docs/cases/baemin.md §3-3 |
