# A/B 테스트 설계 및 실습: 이론 파트 PPT 제작 가이드

> 이론 파트(75분) 슬라이드를 만들 때 기준으로 쓰는 문서입니다. 실습(설계서 작성, 결과 해석 실습, Power Analysis 데모)과 함정·해석·공유 세션(30분)은 범위에서 뺐습니다.
> 세부 구성은 발표자가 정하되, **2장 세션 방향성**과 **4장 필수 커버 개념**은 지켜주세요.

## 1. 세션 개요

| 항목 | 내용 |

| 세션명 | A/B 테스트 설계 및 실습 |

## 2. 세션 방향성 (가장 중요)

이 세션은 통계 수업이 아니라 **실무에서 실험을 설계하고, 결과를 바르게 해석하고, 함정을 피하는 세션**입니다. 통계는 도구로만 쓰고 무게중심은 설계와 해석에 둡니다.

| 이렇게 간다 (실무 실험가 관점) | 이건 피한다 (수식 유도 강의) |
| --- | --- |
| 가설 → 설계 → 해석 → 의사결정의 전체 흐름 | t검정·카이제곱 수식 유도·증명 |
| 통계 수치를 실무 언어로 번역 ("p<0.05"가 아니라 "배포할까 말까") | 이론을 깊게 파다 설계·해석을 못 다루는 것 |
| 실무에서 실제로 밟는 함정을 미리 경험 | 사례 없이 공식만 나열 |

**슬라이드 작성 원칙**

- 통계 개념 슬라이드는 "정의 → 언제 쓰나 → 실무에서 어떻게 말하나" 순서로. 수식은 꼭 필요할 때 한 줄만.
- 공통 3주차 통계와 겹치지 않게 한다. 가설검정 기초를 다시 설명하지 말고 "이미 배운 z-test를 A/B 테스트에 어떻게 쓰나"로 진행한다.
- 참가자 통계 기초가 약하면 오프닝에 **초압축 복습(최대 10분)** 슬라이드를 넣되, 설계·해석이라는 본질을 벗어나지 않게 한다.
- 개념마다 실제 기업 사례나 숫자 예시를 하나씩 붙인다.

## 3. 이론 파트 타임라인과 챕터 구성

이론 75분 안에 세부 목차 1~5장을 모두 담습니다. 시간은 세부 목차의 비중(15/25/25/20/10%, 실습 5% 제외)을 75분에 맞춰 다시 나눈 값입니다. 밀도가 높으니 타임박싱을 철저히 하세요.

| 챕터 | 비중 | 시간 |
| --- | --- | --- |
| Ch1 실험 설계의 기초와 인과추론 (오프닝 포함) | 15% | 약 12분 |
| Ch2 A/B 테스트 설계의 핵심 구성요소 | 25% | 약 20분 |
| Ch3 실험 실행과 통계 분석 | 25% | 약 20분 |
| Ch4 실무 함정과 고급 설계 | 20% | 약 15분 |
| Ch5 산업 사례와 실험 문화 + 의사결정 정리 | 10% | 약 8분 |
| **합계** | | **75분** |

> 실습(75분)과 함정·해석·공유(30분)는 이 PPT 범위 밖입니다. Ch4에서는 함정을 **개념으로 소개**하고, 직접 겪어보는 것은 뒤의 함정 세션에 맡깁니다.

### Ch1. 실험 설계의 기초와 인과추론 (약 12분)

- **세부 목차**
  - 오프닝 질문: "그냥 배포하고 보면 안 되나?"
  - 상관관계 vs 인과관계 (Simpson's Paradox, Confounding)
  - 왜 실험이 필요한가: 관찰 데이터의 한계, "바꿔보고 지표 오르면 성공?"의 위험
  - 무작위 통제 실험(RCT)의 원리: 랜덤 배정이 왜 인과 주장을 가능하게 하는가
  - A/B 테스트의 정의와 비즈니스 의사결정에서의 역할
  - A/B 테스트가 안 되는 상황(윤리, 네트워크 효과 등) 짧게 언급
- **필수 개념**: 인과추론(Causal Inference) / Potential Outcomes Framework, 내적 타당성(Internal Validity) vs 외적 타당성(External Validity), Selection Bias

### Ch2. A/B 테스트 설계의 핵심 구성요소 (약 20분)

- **세부 목차**
  - 가설 수립: "무엇을, 왜 바꾸면, 어떤 지표가 어떻게 변할 것이다" / H0 vs H1, 단측·양측검정
  - 핵심 지표 설계: OEC(Overall Evaluation Criterion), Primary / Guardrail / Secondary Metric. OEC는 그로스 세션의 노스스타와 연결
  - 대조군/실험군, 표본의 대표성
  - 실험 단위 결정: User-level vs Session-level vs Page-level
  - 표본 크기 산정(Power Analysis): 유의수준(α), 검정력(1-β), MDE. "얼마나 많은 유저가 필요한가"로 설명
  - 무작위 배정: 단순 vs 층화(Stratified), 해싱 기반 배정
- **필수 개념**: OEC / MDE, Statistical Power(통상 80%) / 유의수준(통상 5%), 1종 오류(False Positive) / 2종 오류(False Negative), SUTVA, Guardrail Metric(페이지 로딩 시간, 에러율 등. 개선하려다 다른 지표를 망가뜨리지 않게)

### Ch3. 실험 실행과 통계 분석 (약 20분)

- **세부 목차**
  - A/A 테스트: 시스템 검증과 기저 분산 측정
  - Ramp-up 전략: 1% → 5% → 50% 단계적 확대
  - 실험 기간 결정: 최소 1~2주 (요일 효과, 신기효과)
  - 통계 검정: z-test, t-test, Chi-squared test. **수식 없이 "언제 뭘 쓰나"만**
  - p-value와 신뢰구간의 올바른 해석. 점추정보다 구간으로 말하기
  - 효과 크기(effect size): 통계적 유의 ≠ 실질적 의미
  - 분산 축소 기법: CUPED, 층화 분석, Delta Method
  - 다중검정 문제: Bonferroni, FDR (Benjamini-Hochberg)
- **필수 개념**: A/A 테스트, CUPED(실험 전 데이터로 분산 축소, Microsoft 제안), Peeking Problem(중간 확인 시 1종 오류율 증가), Novelty Effect / Primacy Effect, Multiple Comparison Problem

### Ch4. 실무 함정과 고급 설계 (약 15분)

- **세부 목차**
  - p-hacking / 다중 검정: 여러 지표를 마구 보다 하나 걸리면 성공?
  - 조기 종료(Peeking) → Sequential Testing (Always-Valid p-values)
  - 심슨의 역설: 전체와 세그먼트별 결과가 뒤집히는 현상
  - 신규성 효과 / 학습 효과: 초반 반응이 오래 가지 않음
  - Sample Ratio Mismatch(SRM): 배정 비율 불일치 탐지, 실험 오염 신호
  - Survivorship Bias / Network Effect(Spillover) / Instrumentation Effect
  - 고급 설계 (짧게 소개): Multi-armed Bandit(Thompson Sampling, UCB, epsilon-greedy), Switchback Experiment(배달, 라이드쉐어), Cluster Randomization, Interleaving(검색/추천)
  - 실험이 불가능할 때의 대안: DID, RDD, Synthetic Control
- **필수 개념**: SRM / Sequential Testing, Multi-armed Bandit(탐색 vs 활용), DID(Difference-in-Differences), Switchback Design

### Ch5. 산업 사례와 실험 문화 (약 8분, 마무리 포함)

- **세부 목차**
  - Microsoft (Bing): OEC 설계와 CUPED 도입
  - Netflix: Interleaving 추천 실험
  - Booking.com: 실험 민주화 문화
  - Uber/Lyft: Switchback 실험
  - 한국: 토스, 쿠팡, 카카오 실험 문화
- **필수 개념**: 실험 민주화(Democratization of Experimentation), Feature Flag, Experimentation Platform

### 마무리: 의사결정으로 닫기 (Ch5 끝에 1~2장)

- "유의미하다"에서 멈추지 말고 **"그래서 배포한다 / 안 한다 / 재실험한다"**로 끝낸다.
- 효과 크기 × 비용 × 리스크를 함께 보는 판단 프레임을 한 장으로 정리한다.

## 5. 다른 세션과의 연결 (오프닝·클로징 슬라이드용)

| 연결 세션 | 연결 포인트 |
| --- | --- |
| ← 공통 3주차 통계 | 가설검정·p-value·신뢰구간 기초를 실전으로 확장. 복습이 아니라 적용 관점 |
| ← 그로스 세션 | 그로스에서 세운 "개선 가설"을 여기서 "실험으로 검증". 진단 → 검증 흐름 |
| ← 시각화 세션 | 실험 결과를 대시보드로 모니터링하는 감각 |
| DA 트랙 전체 | 뽑고(SQL) → 보고(시각화) → 진단하고(그로스) → 검증한다(A/B). 이 세션이 트랙을 하나의 의사결정 흐름으로 닫는다 |

### 위키 09편 실무 (1) 반영 (2026-10-07)

덱 Ch3와 겹치는 내용(A/A 기본, 램프업 단계, 검정 선택, p-value, 신뢰구간, 다중검정, Peeking, CUPED 기본)은 넣지 않고, 위키에만 있는 내용을 기존 슬라이드에 녹였습니다.

| 슬라이드 | 녹인 내용 |
| --- | --- |
| 실행 순서 | 1% 단계에서 노출·로깅 기록 확인, "램프업은 위험을 제한하는 절차, 1%에서 좋아 보인다고 늘리면 Peeking과 같다" |
| A/A 테스트 | 파이프라인 점검(배정 → 노출 → 로깅 → 지표 계산 → 분석과 영역별 문제), "한 번 유의했다고 고장은 아니다"와 봐야 할 패턴 |
| 실험 기간 | "'무조건 2주' 규칙은 없다"와 판단 기준 세 가지 |
| 신뢰구간 | 95% 신뢰구간의 엄밀한 의미 |
| 효과 크기 | 결과 읽는 순서: 효과 크기 → 신뢰구간 → p-value → 의사결정 |
| 분산 축소 | θ = Cov(Y, X)/Var(X), 분산 Var(Y)(1 - ρ²) |
| 다중검정 | Bonferroni(FWER)와 BH(FDR)의 통제 대상·쓰임 |
| CUPED 주의점 (신규 1장) | 상관이 낮으면 효과 작음, 실험 전 변수만, 신규 사용자, 잘못된 설계는 못 고침 |
