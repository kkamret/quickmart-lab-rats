# 사례 ② 토스: 푸시 디타게팅 ABC 테스트

## 0. 메타
- 원문: 토스 기술 블로그 「진짜 A/B 테스트: 토스의 푸시 생태계를 데이터로 재설계한 방법」(고은솔, 2025.10.01) https://toss.tech/article/data-analyst-ab-test
- 화면 속 서비스명: 원문 각색임을 명시하고 "토스"를 쓰되, 모든 수치는 가상
- 난이도 ★★★ / 권장: 통계 기초가 탄탄한 조
- 커버 개념: 관찰 데이터의 교란(타겟팅 편향), 오프라인 시뮬레이션 vs 온라인 실험, A/B/n(ABC), **처치가 분모를 바꾸는 비율 지표**, 배정 단위 ≠ 분석 단위(Delta Method), 비열등성 검정, CUPED, 장기 효과(습관 침식), 다중검정(서비스별 가드레일), Ramp-up(6% → 30%), 이질적 처치 효과(HTE), 리스크 기반 배포안 선택, 이해관계자 합의

### 원문에서 확인된 사실 (Readout 방향은 반드시 이와 일치)
- 가입자 2,900만, 서비스 100개 이상으로 늘며 푸시 발송량 증가, 전사 푸시 CTR 점진 하락
- EDA: 서비스·템플릿·메시지 목적 분해, 세그먼트별 반응, SHAP로 주요 피처 식별. "푸시를 많이 받을수록 CTR이 낮다"는 직관은 정교한 타겟팅 때문에 단순 비교로는 왜곡될 수 있음
- 디타게팅 룰: 최근 N일 동안 동일·유사 목적 푸시에 N회 연속 무반응이면 해당 카테고리 푸시를 일정 기간 제외(쿨다운). 최적 N은 시뮬레이션으로 후보 도출
- 실험: 전체 유저 6% 무작위 추출, Control vs Variant 1(진보적 N) vs Variant 2(보수적 N), 2개월. 주 지표 푸시 CTR, 보호 지표 앱 오픈 AU·서비스별 AU·매출
- 결과: 두 변이안 모두 CTR 약 +4%p, V1이 V2보다 약 +0.5%p 추가. 발송량 의미 있게 감소, 클릭 총량 유지, 가드레일 유의한 악화 없음
- 30%로 확장해 6주 추가 관찰, 결과 동일 → 리스크 최소화를 위해 **보수안(V2)으로 전사 배포**
- 실험 전 목적·가설·보호 지표·리스크를 각 제품 담당자와 투명하게 공유하고 합의
- 다음 단계: 유저·서비스별로 N을 동적으로 조정
- 교육용 추가 요소(원문에 없음, 화면에 표기): CUPED, 비열등성 검정, 라이트 유저 습관 침식 신호, 서비스 담당자 반발 이벤트

## 1. 고정 모집단 (SEED = 20251001)

- 실험 모집단: 최근 30일 푸시 수신자 2,400만 명
- 세그먼트(활동성): heavy 0.30 / medium 0.45 / light 0.25
- 주당 수신 푸시(대조군): heavy 16 / medium 8 / light 4
- 메시지 목적 비중: 정보성 0.35 / 프로모션 0.45 / 리텐션 0.20
- 기본 푸시 CTR(대조군, 푸시 단위): heavy 14.5% / medium 10.5% / light 6.5% → 발송 가중 전체 약 12.1%
  - 목적별 배수: 정보성 ×1.6, 프로모션 ×0.6, 리텐션 ×0.9 (세그먼트 평균이 위 값이 되도록 정규화)
- 주간 앱 오픈 AU(배정 사용자 중 주 1회 이상 앱 오픈): heavy 0.93 / medium 0.66 / light 0.28 → 전체 약 0.64
- 서비스별 AU: 서비스 S01~S12 (S10~S12는 저빈도 서비스, 푸시 의존도 높음)
- 인당 주간 매출: 0 질량 0.82 + 로그정규(평균 9,000원, 꼬리 두꺼움)
- 알림 수신 거부율(월): 0.30%

### 1-1. 사용자 적률 모델 (Delta Method용)
엔진은 고정 시드로 **대표 사용자 60,000명**을 생성해 정책별 (주간 발송 수 S, 클릭 수 C)의 평균·분산·공분산을 세그먼트별로 계산한다. 그다음 실제 표본 크기 n에 맞춰 그룹 집계를 CRN 노이즈로 생성한다.
- 사용자 단위 CTR 비율 SE: `deltaRatio(mean C, mean S, Var C, Var S, Cov(C,S), n)`
- 푸시 단위(순진한) SE: 총 발송 수를 n으로 보는 이항 SE → 실제보다 약 2.5~3.5배 좁게 나와야 함. 기간이 길수록 같은 사용자의 푸시가 많이 묶여 비율이 커짐(8주 ≈ 2.8배, 12주 ≈ 3.4배, 6주 미만은 2.5배 아래)
- CUPED 공변량: 실험 전 4주 인당 클릭 수(ρ = 0.70), 실험 전 4주 앱 오픈 여부(AU에 대해 ρ = 0.60)

### 1-2. s1 관찰 데이터 (EDA용, 대조군 과거 데이터)
- 주간 수신량 구간별 CTR(풀링): 1~3개 15.8% / 4~7개 12.9% / 8~15개 10.4% / 16개 이상 8.1% → 강한 음의 관계
- 같은 세그먼트·같은 목적 안에서 보면 기울기가 훨씬 완만: 주당 1개 추가 시 −0.08%p (이게 진짜 피로 효과)
- 풀링 기울기가 가파른 이유: 많이 받는 사람은 heavy 사용자이고, 이들은 프로모션(저CTR)을 많이 받음 → 구성 효과 + 타겟팅 편향
- 패널: 산점도(풀링), 층화 테이블(세그먼트 × 목적), SHAP 스타일 피처 중요도 막대(빈도, 최근 클릭, 카테고리 적합도, 수신 시각)

## 2. 정책 메커니즘과 진짜 효과 (숨김)

### 2-1. 디타게팅 규칙 파라미터
- W: 무반응 관찰 창 7 / 14 / 30일
- N: 연속 무반응 횟수 2 / 3 / 4 / 5 / 6 / 8
- C: 쿨다운 7 / 14 / 30일
- G: "유사 목적" 묶음 범위 `same_service`(같은 서비스만) / `same_purpose`(서비스를 넘어 같은 목적 전체)

### 2-2. 발송 감소율 s (진짜 값, 오프라인 리플레이도 거의 정확)
- 기준표(W=14, C=14, G=same_service): N=2: 34% / 3: 25% / 4: 20% / 5: 16% / 6: 13% / 8: 9%
- 배수: W 7일 ×0.80, 30일 ×1.12 / C 7일 ×0.75, 30일 ×1.15 / G same_purpose ×1.20 / 상한 55%
- 세그먼트별 분배: 억제는 heavy·medium의 프로모션 스트림에 집중(heavy ×1.1, medium ×1.0, light ×0.8)

### 2-3. 억제된 푸시의 과거 CTR (ctr_supp)
N=2: 2.5% / 3: 1.6% / 4: 1.2% / 5: 1.0% / 6: 0.9% / 8: 0.8%

### 2-4. 인당 클릭 변화 (진짜 값)
- 오프라인 손실 추정 `L_off = s × ctr_supp / 12.1%` (리플레이는 억제된 푸시의 과거 클릭을 전부 잃는다고 가정)
- 온라인 진짜 변화 `ΔC = −0.25 × L_off + 0.012 × s` (피로 완화로 남은 푸시 반응이 회복되어 손실의 75%가 상쇄 + 소폭 회복)
- 결과적으로 오프라인 리플레이는 클릭 손실을 **약 5~8배 과대추정**(REF_V1 ≈ 6.3배, REF_V2 ≈ 7.7배, N=2 ≈ 5.2배) → 조가 보수적으로 고를 유인. 원문 "시뮬레이션과 거의 일치"와의 차이는 reveal에서 "리플레이 가정에 따라 달라질 수 있다"로 설명

### 2-5. CTR (파생)
`CTR_v = 12.1% × (1 + ΔC) / (1 − s)` → 대부분 **구성 효과(분모 축소)**로 오른다

### 2-6. 장기 습관 침식 (교육용 추가, 숨김)
- light 세그먼트 앱 오픈 AU: `−0.4% × max(0, (s − 0.20) / 0.05)` (상대), 노출 **5주차부터** 나타나 8주차에 완전 반영
- s5 확대 실험은 기존 6% 코호트(이미 장기 노출)와 신규 편입 사용자를 함께 집계한다. 기존 코호트는 침식이 완전 반영된 상태로 시작
- G = same_purpose면 ×1.3
- 저빈도 서비스 S10~S12의 서비스 AU에는 ×3으로 집중
- heavy·medium AU, 매출: 진짜 효과 0
- 알림 수신 거부율: 상대 `−0.35 × s` (좋아짐)

### 2-7. 원문 대조 기준 변이안 (테스트 고정값)
- REF_V1 (진보): N=3, W=14, C=14, same_service → s ≈ 25%, ΔC ≈ −0.5%, CTR ≈ 16.0% (+3.9~4.1%p)
- REF_V2 (보수): N=4, W=30, C=14, same_service → s ≈ 22.4%, ΔC ≈ −0.3%, CTR ≈ 15.5% (+3.4~3.6%p)
- V1 − V2 CTR ≈ +0.5%p

## 3. 설계 입력 (zod) → 결과 반영

### 3-1. s1_diagnose
```ts
{ chosen_analysis: 'pooled'|'stratified'|'both',
  predicted_ctr_gain_pp: number,          // "발송 20% 감소 시 CTR 변화" 예측
  causal_claim: 'yes'|'no'|'unsure', rationale: string }
```
- 채점: stratified/both 선택, 인과 주장 'no', 예측 CTR 상승분 중 대부분이 구성 효과임을 언급하면 만점
- 순진한 풀링 기울기 기반 예측(약 +4.5%p 이상의 "행동 변화")은 RATIO_COMPOSITION 오해로 기록

### 3-2. s2_design
```ts
{
  hypothesis: { action; behavior; impact },
  variants: [{ name:'V1', N, W, C, G }, { name:'V2', N, W, C, G }],   // 2개 필수
  sample_fraction: number,        // 0.01~0.20 (전체 2,400만 중), 3군 균등 배정
  duration_weeks: number,         // 2~12
  primary: 'push_ctr'|'clicks_per_user'|'app_open_au'|'sends_per_user',
  hypothesis_type: Record<MetricKey, 'superiority'|'non_inferiority'>,
  ni_margin_pct?: number,         // 비열등성 마진 (예: −1%)
  guardrails: ('app_open_au'|'service_au'|'revenue_per_user'|'opt_out_rate')[],
  secondary: MetricKey[],
  ctr_analysis_unit: 'push'|'user_delta',
  cuped: boolean,
  correction: 'none'|'bonferroni'|'bh',
  stopping: 'fixed'|'peek_stop'|'sequential',
  stakeholder_alignment: boolean, // 서비스 담당자에게 목적·가드레일·리스크 사전 공유
}
```
- 제출 전 **오프라인 리플레이 패널**: 변이안별 발송 감소율, 오프라인 클릭 손실 추정(과대추정된 값), 세그먼트별 억제 분포

### 3-3. 반영 규칙
| 설계 | 규칙 |
|---|---|
| sample_fraction, duration | 그룹당 n = 2,400만 × fraction / 3. 주간 시계열 생성 |
| primary = push_ctr 이고 clicks_per_user가 어디에도 없음 | `RATIO_COMPOSITION` (CTR 상승이 클릭 증가인지 분모 축소인지 구분 불가) |
| ctr_analysis_unit = push | SE를 푸시 단위 이항으로 계산 → 과도하게 좁음, 서비스별 표에서도 작은 차이가 유의해짐 → `NAIVE_SE` |
| hypothesis_type(clicks) = non_inferiority | 단측 비열등성 검정 결과(마진 대비) 표시. superiority면 "차이 없음"으로만 나와 "유지"를 주장할 근거가 약함을 해설 |
| cuped = true | 해당 지표 분산 × (1 − ρ²). AU 침식 같은 작은 효과의 검출력이 크게 오름 |
| 종료 주차(stoppedAt) < 6 이고 max(s) ≥ 0.20 (A/A 제외) | 습관 침식이 데이터에 나타나기 전 종료 → `SHORT_DURATION`. 코드 규칙은 실제 종료 주차 기준이라 duration_weeks < 6 은 물론, 6주 이상으로 설계해도 중간 확인으로 일찍 멈추면 뜬다. A/A 는 진짜 효과가 없어서 뜨지 않는다 |
| guardrails에 service_au 포함 | 12개 서비스 × 2 비교 = 24개 검정 표. correction=none이면 우연히 1~2개 유의(CRN 고정) → `MULTIPLE_TESTING` |
| peek_stop | 주간 누적 검정(첫 변이안 vs 대조군, 메인 지표). 메인이 CTR(또는 발송 수)이면 첫 주부터 유의 → 1주차에 종료되어 침식 미관측 → `PEEKED` + `SHORT_DURATION`. 메인이 인당 클릭·AU 처럼 효과가 작은 지표면 끝까지 갈 수 있지만, 매주 들여다본 것 자체가 거짓 양성을 부풀리므로 종료 주차와 무관하게 `PEEKED` |
| sequential | O'Brien-Fleming 경계로 주간 확인. 메인이 CTR(또는 발송 수)이면 효과가 커서 경계를 1주차에 넘어 **sequential 도 1주차에 종료** → `SHORT_DURATION`(`PEEKED` 는 아님). 경계가 오류율을 지켜도 종료 시점이 침식 관측 전이라는 문제는 남는다 |
| stakeholder_alignment = false | s5에서 "저빈도 서비스 담당자 2명이 도달 감소를 이유로 실험 중단 요청" 이벤트 발생. 대응안 제출 필수 |
| variants가 공격적(s ≳ 0.33) | s ≈ 0.33 부근은 경계선(p ≈ 0.05), s ≈ 0.38 부터는 light AU 침식이 6% 표본·8주에서도 안정적으로 유의하게 드러남(정상 작동, 가드레일이 지켜주는 사례). same_purpose 는 침식 ×1.3 이라 같은 s 에서 더 잘 드러남 |

### 3-4. s4 Readout 구성
- SRM(3군), 지표 표(V1 vs A, V2 vs A, V1 vs V2), 비열등성 결과, 주간 시계열(CTR·인당 클릭·light AU), 서비스별 AU 표(24개), 매출(꼬리 지표, 평균과 윈저라이즈 평균 둘 다), 발송 감소율, 알림 거부율
- 패널 `composition`: CTR 변화 분해 = 구성 효과(억제된 저CTR 푸시 제거) + 행동 효과(남은 푸시 반응 변화). **조가 primary에 clicks_per_user를 넣었을 때만 활성화**(그 전엔 "인당 클릭 데이터가 필요해요" 안내)

### 3-5. s5_deep (30% 확대)
```ts
{ arms: ('A'|'V1'|'V2')[], fraction_total: number /*≤0.30*/, duration_weeks: number /*≥2*/,
  cuped: boolean, correction, response_to_stakeholders?: string }
```
- 패널 `hte`: 세그먼트(heavy/medium/light) × 변이안별 CTR·인당 클릭·AU 효과와 CI
- 원문 대조: CUPED 없이 보면 V1·V2 모두 가드레일 유의 악화 없음(원문과 동일). CUPED를 켜면 V1의 light AU 하락이 경계선(p ≈ 0.03~0.08) 부근으로 드러남 → 보수안 선택의 정량 근거
- 서비스 담당자 이벤트 대응안(텍스트)은 AI 리뷰 대상

### 루브릭 요지
- 메인을 CTR 하나로 두면 감점, 인당 클릭(비열등성)과 짝지으면 가산
- 사용자 단위 분석(Delta Method), CUPED, 서비스 표 보정 사용 시 가산
- 기간 6주 이상 또는 장기 효과 관찰 계획이 있으면 가산
- 배포 근거에 "효과 크기 × 도달 손실 × 리스크 비대칭"과 이해관계자 합의가 들어가면 만점

### reveal 해설 요지
원문은 두 변이안 모두 CTR 약 +4%p, 클릭 총량 유지, 가드레일 악화 없음을 확인하고 30% 확대 후 보수안을 배포했다. CTR 상승이 "불필요한 푸시를 덜 보낸 결과"임을 클릭 총량으로 함께 증명한 것이 핵심이고, 진보안의 추가 +0.5%p보다 리스크를 줄이는 쪽을 택했다. 다음 단계로 유저·서비스별 동적 N을 연구 중이다.
